# Дополнительные спецификации HabitFlow C++ (Supplementary Specification)

Настоящий документ содержит спецификацию общих, нефункциональных и системных требований к настольному приложению **HabitFlow C++**, которые не привязаны к отдельным вариантам использования (Use Cases), а действуют сквозным образом на всю проектируемую систему. Спецификация структурирована по международной модели качества **FURPS+** (согласно ISO/IEC/IEEE 29148 и ISO/IEC 25010).

---

## 1. Функциональные общие требования (Functionality)

### 1.1 Стандарты форматов данных
- **SUPP-FUNC-001 (Формат JSON):** Основная база данных приложения `habits_db.json` должна строго соответствовать стандарту **RFC 8259**. Кодировка файла — UTF-8 без BOM. Все ключи и строковые значения должны быть экранированы согласно спецификации JSON.
- **SUPP-FUNC-002 (Формат экспорта CSV):** Файл выгрузки истории `export_history.csv` должен соответствовать стандарту **RFC 4180**. В начале файла обязателен байтовый маркер порядка байтов **UTF-8 BOM** (`0xEF, 0xBB, 0xBF`) для автоматического корректного распознавания кириллических заголовков в Microsoft Excel и LibreOffice Calc. В качестве разделителя полей используется точка с запятой (`;`).

### 1.2 Математический расчет суточной дисциплины
- **SUPP-FUNC-003 (Формула интегральной дисциплины):** Вычисление суточного процента дисциплины $D$ должно выполняться по взвешенной аддитивной формуле:
  $$D = \left( 0.25 \cdot S + 0.20 \cdot \frac{M_{fact}}{M_{target}} + 0.20 \cdot \min\left(1.0, \frac{W_{fact}}{W_{target}}\right) + 0.20 \cdot \min\left(1.0, \frac{A_{fact}}{A_{target}}\right) + 0.15 \cdot \frac{B_{fact}}{B_{target}} \right) \times 100\%$$
  где:
  - $S \in \{0, 1\}$ — факт соблюдения нормы сна ($1$, если $T_{sleep} \ge T_{target}$, иначе $0$);
  - $M_{fact}, M_{target}$ — количество выполненных и запланированных приемов пищи;
  - $W_{fact}, W_{target}$ — объем фактически выпитой и целевой воды (мл);
  - $A_{fact}, A_{target}$ — продолжительность прогулки на свежем воздухе (мин);
  - $B_{fact}, B_{target}$ — количество выполненных 10-минутных пауз отдыха по таймеру 50/10.

## 2. Эргономика и удобство использования (Usability)

- **SUPP-USE-001 (Эргономика быстрого ввода):** Для частых ежедневных операций (например, добавление выпитой воды) интерфейс должен предоставлять кнопки быстрого инкремента (`+250 мл`, `+500 мл`) без вызова модальных окон подтверждения.
- **SUPP-USE-002 (Цветовая индикация матрицы календаря):** Ячейки интерактивного календаря дисциплины должны иметь однозначную цветовую кодировку:
  - Зеленый цвет (`#22C55E` / `#16A34A`): $D \ge 80\%$ (день успешен, стрик продлен);
  - Желтый цвет (`#EAB308` / `#CA8A04`): $50\% \le D < 80\%$ (частичное выполнение);
  - Красный цвет (`#EF4444` / `#DC2626`): $D < 50\%$ (срыв режима);
  - Нейтральный серый цвет (`#94A3B8`): отсутствие введенных данных за дату.
- **SUPP-USE-003 (Адаптивная стилизация QSS):** Графический интерфейс должен быть полностью кастомизирован с помощью стилей Qt Style Sheets (QSS). Контрастность текста по отношению к фону карточек должна составлять не менее 4.5:1 (согласно рекомендациям WCAG 2.1 AA).
- **SUPP-USE-004 (Всплывающие подсказки Tooltip):** Наведение курсора мыши на любую ячейку календаря или индикатор прогресса должно вызывать информативную подсказку с детализацией по каждой из 5 привычек за 0.3 секунды.

## 3. Надежность и сохранность данных (Reliability)

- **SUPP-REL-001 (Паттерн атомарной записи Air-gap Persistence):** Сохранение изменений в базу данных должно исключать повреждение файла `habits_db.json` при внезапном отключении электропитания или аварийном завершении процесса:
  1. Сериализация в новый временный файл с суффиксом `habits_db.json.tmp`;
  2. Принудительный сброс дискового кэша ОС на физический накопитель вызовом `fsync()` (POSIX) или `FlushFileBuffers()` (Windows);
  3. Атомарная замена целевого файла через `std::filesystem::rename()`.
- **SUPP-REL-002 (Автоматическое резервное копирование):** При каждом успешном запуске приложения создается резервная копия файла базы данных `habits_db.json.bak`. В случае обнаружения синтаксической ошибки парсинга основного файла, приложение автоматически восстанавливает рабочее состояние из `.bak`.
- **SUPP-REL-003 (Автономность работы Off-line):** Приложение функционирует на 100% локально, не требует сетевого соединения с интернет-серверами и не передает пользовательские персональные данные во внешние сети.

## 4. Требования к производительности (Performance)

- **SUPP-PERF-001 (Время холодного запуска):** Время инициализации приложения с момента клика по ярлыку до полной отрисовки главного окна не должно превышать **800 миллисекунд** на персональном компьютере офисного класса (процессор с тактовой частотой от 2.0 ГГц, накопитель SSD).
- **SUPP-PERF-002 (Отклик интерфейса при перерасчете):** Полный перерасчет интегрального процента дисциплины и обновление всех связанных графических элементов (виджет стрика, шкала дня, ячейка календаря) при изменении любого поля должно занимать не более **5 миллисекунд**.
- **SUPP-PERF-003 (Атомарная фиксация на диск):** Полный цикл сериализации, вызова `fsync()` и атомарного переименования файла на физическом накопителе должен выполняться не более чем за **25 миллисекунд**.
- **SUPP-PERF-004 (Потребление оперативной памяти):** Объем потребляемой приложением динамической памяти (Resident Set Size, RSS) в фоновом режиме работы в системном трее не должен превышать **50 Мегабайт**.

---

## 5. Сопровождаемость и переносимость (Supportability)

- **SUPP-SUPP-001 (Стандарт языка программирования):** Исходный код ядра приложения должен быть написан на чистом стандарте **C++17 (ISO/IEC 14882:2017)** с использованием библиотеки STL и нулевым количеством сторонних внешних зависимостей.
- **SUPP-SUPP-002 (Кроссплатформенность GUI):** Графическая подсистема должна использовать фреймворк **Qt 6 Widgets (C++)**, гарантируя компиляцию и идентичное отображение в операционных системах семейств Microsoft Windows 10/11 (MSVC / MinGW) и GNU/Linux (GCC / Clang).
- **SUPP-SUPP-003 (Система автоматизации сборки):** Сборка всего проекта, управление компилятором и линковкой библиотек должны осуществляться через кроссплатформенную систему **CMake** версии не ниже 3.20.

---

## 6. Ограничения проектирования и интерфейсы (Constraints & Interfaces)

- **SUPP-CONST-001 (Изоляция слоев MVP):** Модуль бизнес-логики (`core/`) не должен содержать включений заголовочных файлов Qt (`#include <QWidget>`, `#include <QString>`), взаимодействуя с презентером исключительно через стандартные типы C++ (`std::string`, `double`, `std::vector`).
- **SUPP-CONST-002 (Интеграция со службой System Tray):** При сворачивании окна приложения через системную кнопку закрытия или минимизации, процесс не завершается, а переходит в фоновое отслеживание таймера 50/10 с размещением иконки в системном трее ОС.
