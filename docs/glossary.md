# Глоссарий проекта HabitFlow C++ (Project Glossary)

Настоящий документ представляет собой официальный глоссарий терминов, определений и акронимов предметной области и архитектуры десктопного приложения **HabitFlow C++**. Документ разработан в соответствии с требованиями лабораторной работы №5 по дисциплине «Жизненный цикл разработки программного обеспечения» и оформлен в виде стандартизированной таблицы.

## Таблица терминов и определений

| № | Термин (рус.) | Термин (англ.) | Определение и семантика в системе HabitFlow | Диапазон значений / Формат / Пример |
| :-: | :--- | :--- | :--- | :--- |
| 1 | **Привычка** | Habit | Повторяющееся регулярное действие пользователя, направленное на поддержание здорового распорядка дня (сон, вода, питание, прогулка, перерывы). | Перечень базовых сущностей системы (5 базовых привычек). |
| 2 | **Суточная запись** | Daily Habit Record | Атомарный набор фактических данных о выполнении привычек пользователем за конкретную календарную дату. | Структура `HabitRecord` (дата ISO 8601 `YYYY-MM-DD`, числовые и булевы поля). |
| 3 | **Интегральная дисциплина** | Daily Discipline Score | Взвешенный процент выполнения суточной нормы здоровья, рассчитываемый по формуле многофакторной свертки. | Вещественное число от 0.0% до 100.0%. $D \ge 80\%$ считается успешным днем. |
| 4 | **Стрик (Серия)** | Habit Streak | Количество подряд идущих календарных дней, в каждый из которых интегральный процент дисциплины составил не менее 80%. | Целое неотрицательное число (0, 1, 2, ... дней). Сбрасывается при $D < 80\%$. |
| 5 | **Личный рекорд стрика** | Longest Streak Record | Исторический максимум непрерывной серии успешных дней, зафиксированный за все время эксплуатации приложения. | Целое число $\ge$ текущему стрику. |
| 6 | **Норма сна** | Sleep Target Norm | Целевое количество часов ночного отдыха, настраиваемое пользователем в параметрах профиля. | Число с плавающей точкой в диапазоне [4.0 .. 12.0] часов; по умолчанию 8.0 ч. |
| 7 | **Водный баланс** | Water Balance | Объем чистой питьевой воды, употребленной пользователем в течение текущих суток. | Целое число миллилитров в диапазоне [0 .. 10000] мл; шаг быстрой кнопки +250/+500 мл. |
| 8 | **Регулярность питания** | Meal Regularity | Доля выполненных основных приемов пищи (завтрак, обед, ужин) от целевого суточного плана. | Вещественное значение [0.0 .. 1.0], вычисляемое как $\frac{N_{fact}}{N_{target}}$ (по умолчанию 3 приема). |
| 9 | **Цикл отдыха 50/10** | 50/10 Rest Interval | Эргономический режим чередования непрерывной работы за монитором (50 мин) и физической разминки (10 мин). | Временные интервалы таймера: 3000 секунд работы и 600 секунд отдыха. |
| 10 | **Атомарное сохранение** | Atomic Persistence | Механизм гарантированной записи данных в постоянное хранилище без риска повреждения файла при внезапном сбое питания. | Паттерн Write-Temp-Sync-Rename (`.tmp` $\rightarrow$ `fsync()` $\rightarrow$ `std::filesystem::rename()`). |
| 11 | **Сброс буферов (fsync)** | File Flush (fsync) | Системный вызов операционной системы, принудительно переносящий данные из дискового кэша ОЗУ на физический накопитель. | POSIX `fsync()` в Linux или `FlushFileBuffers()` в ОС Windows. |
| 12 | **Хранилище JSON** | JSON Database | Локальный текстовый файл в формате RFC 8259 UTF-8, содержащий массив исторических записей и профиль настроек. | Файл `habits_db.json` в локальной директории данных пользователя. |
| 13 | **Резервная копия** | Backup File | Теневая копия базы данных, создаваемая перед выполнением операций перезаписи и миграции схемы. | Файл `habits_db.json.bak`. |
| 14 | **Диагностический лог** | Error Log | Текстовый журнал регистрации аппаратных сбоев ввода-вывода, повреждений JSON-схемы и системных исключений. | Файл `habits_error.log` с метками времени ISO 8601 и кодами ошибок. |
| 15 | **Интерактивный календарь** | Interactive Calendar | Виджет матричного отображения дней месяца, раскрашивающий ячейки по уровню выполнения дисциплины. | Зеленый ($D \ge 80\%$), желтый ($50\% \le D < 80\%$), красный ($D < 50\%$), серый (нет данных). |
| 16 | **Кастомный делегат** | Styled Item Delegate | Компонент графической подсистемы Qt, отвечающий за низкоуровневую отрисовку ячеек таблицы и всплывающих подсказок. | Класс-наследник `QStyledItemDelegate` (`CalendarItemDelegate`). |
| 17 | **Системный трей** | System Tray (Notification Area) | Область уведомлений панели задач операционной системы, в которой размещается фоновая иконка приложения. | Класс `QSystemTrayIcon` со всплывающим контекстным меню и балунами. |
| 18 | **Звуковое оповещение** | Audio Alert | Короткий звуковой сигнал низкой частоты, воспроизводимый при наступлении времени обязательного отдыха от экрана. | Класс `QSoundEffect` и файл `resources/sounds/rest_alert.wav`. |
| 19 | **Экспорт CSV** | CSV Export | Выгрузка полной истории суточных показателей в текстовый табличный формат, совместимый с Excel и LibreOffice. | Файл `export_history.csv` по спецификации RFC 4180 с кодировкой UTF-8 BOM. |
| 20 | **Таблица стилей QSS** | Qt Style Sheets (QSS) | Декларативный язык описания визуального стиля графических элементов управления Qt, аналогичный CSS. | Файл `styles/dark_theme.qss` и `styles/light_theme.qss`. |
| 21 | **Шаблон MVP** | Model-View-Presenter | Архитектурный паттерн, разделяющий бизнес-логику (Model), графический интерфейс (View) и координатор (Presenter). | Интерфейсы `ITrackerView`, класс `HabitPresenter`, слой `Domain`. |
| 22 | **Прецедент** | Use Case | Описание последовательности действий системы в ответ на внешнее событие действующего лица, приносящее ценный результат. | Нотация UML 2.5 (эллипсы с уникальным кодом `UC-1 .. UC-10`). |
| 23 | **Действующее лицо (Актор)**| Actor | Внешняя по отношению к системе сущность (человек, таймер, ОС), взаимодействующая с ней в рамках прецедентов. | Стереотипы `«human actor»` (Пользователь) и `«system actor»` (Таймер, ОС). |
| 24 | **Поток событий** | Flow of Events | Пошаговое формализованное описание взаимодействия актора и системы в рамках выполнения конкретного прецедента. | Включает: Основной поток (Main), Альтернативные (A1, A2), Ошибки (E1). |
| 25 | **Диаграмма активности** | Activity Diagram | Динамическая UML-диаграмма, описывающая алгоритмический поток управления и параллельные ветви бизнес-процесса. | Нотация UML 2.5 (узлы действий, ромбы ветвления, fork/join слияния). |
| 26 | **Диаграмма состояний** | State Machine Diagram | Динамическая UML-диаграмма, моделирующая дискретные состояния сущности и правила переходов между ними по триггерам. | Нотация UML 2.5 (состояния, псевдосостояния `[*]`, триггеры, гарды `[guard]`). |
| 27 | **Диаграмма взаимодействия**| Sequence Diagram | Динамическая UML-диаграмма, отображающая упорядоченный во времени обмен сообщениями между линиями жизни объектов. | Нотация UML 2.5 (Lifelines, Execution Specs, Sync/Async Messages, Return, Ref). |
| 28 | **Предусловие** | Pre-condition | Набор обязательных системных требований и инвариантов, которые должны быть истинными до старта прецедента. | Булево условие (например, «Хранилище инициализировано и доступно на запись»). |
| 29 | **Постусловие** | Post-condition | Гарантированное состояние системы и данных, достигаемое после успешного завершения прецедента. | Булево условие (например, «Запись зафиксирована на физическом диске, UI обновлен»). |
| 30 | **Запрос на изменение** | Change Request (CR) | Официальное предложение Заказчика о добавлении новой функциональности или изменении существующих требований. | Артефакт проектного управления (требование `REQ-SYS-011` / `F11` во 2 раунде). |
